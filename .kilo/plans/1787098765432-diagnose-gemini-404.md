# Plan: Diagnose and Fix Gemini 404 Error

## Problem
The AI request to Gemini returns HTTP 404:
```
"error":"HTTP request returned status code 404"
```

Trace shows the failure at `GeminiGateway::generateStreamStep()` when posting to `models/{$model}:streamGenerateContent?alt=sse`.

## Root Cause Analysis

A 404 from Gemini (rather than 401/403) typically indicates one of:

1. **Model name does not exist** — `BrandingAgent::model()` falls back to `config('ai.providers.gemini.model', env('GEMINI_MODEL', 'gemini-3.5-flash'))`. The config currently contains `'model' => 'gemini-3.5-flash-lite'`, which is not a valid Gemini model identifier. If this fallback chain returns a non-existent model, the API endpoint returns 404.

2. **Base URL misconfiguration** — `CreatesGeminiClient::baseUrl()` reads `$provider->additionalConfiguration()['url'] ?? 'https://generativelanguage.googleapis.com/v1beta/'`. If `GEMINI_URL` env var is set incorrectly (e.g., missing `/v1beta/`, extra path segments, or pointing to a proxy), the constructed endpoint will 404.

3. **Missing API key** — `CreatesGeminiClient::client()` builds headers with `array_filter(['x-goog-api-key' => $provider->providerCredentials()['key']])`. If `GEMINI_API_KEY` is empty, the header is omitted entirely. Some API proxies return 404 rather than 401 to avoid endpoint discovery, making this look like a routing problem.

## Investigation Steps (no code changes yet)

1. **Check what model is actually being sent**
   - Add temporary debug logging in `ChatController::message()` before `$agent->stream($prompt)` to log `$agent->provider()` and `$agent->model()`.
   - Or use tinker: `dd(App\Ai\Agents\BrandingAgent::make(App\Models\Brand::first())->model());`

2. **Check what base URL is being used**
   - Inspect the provider config at runtime: `dd(config('ai.providers.gemini'));`
   - Verify `GEMINI_URL` and `GEMINI_API_KEY` are loaded correctly.

3. **Inspect the actual outgoing request**
   - Temporarily enable HTTP client logging or use a proxy (e.g., `mitmproxy`) to see the exact URL and headers.
   - Or add `\Log::debug('Gemini request', ['url' => $url, 'model' => $model]);` in `GeminiGateway::generateStreamStep()`.

## Proposed Fixes (depending on findings)

### If model name is wrong:
- Update `config/ai.php` `gemini.model` to a valid model like `gemini-2.5-flash-lite` or `gemini-2.5-flash`.
- Update `BrandingAgent::model()` fallback default from `'gemini-3.5-flash'` to `'gemini-2.5-flash'`.

### If base URL is wrong:
- Ensure `GEMINI_URL=https://generativelanguage.googleapis.com/v1beta/` in `.env`.
- If using a proxy, ensure it forwards to the correct Gemini endpoint.

### If API key is missing:
- Set `GEMINI_API_KEY` in `.env`.
- Clear config cache: `php artisan config:clear`.

### If using a proxy/gateway:
- Some corporate proxies return 404 for unauthorized requests. Verify the proxy is passing the `x-goog-api-key` header through.

## Recommended Immediate Action

1. **Add request logging** to `GeminiGateway` or `ChatController` to capture:
   - The exact URL being hit
   - The model name
   - Whether the API key header is present

2. **Verify `.env` values** for:
   - `GEMINI_API_KEY`
   - `GEMINI_URL`
   - `GEMINI_MODEL` (if set)

3. **Update config** to use a confirmed-valid model name.
